# Contributing to pAR3D

Maintained by ProgreTech LLC and Ed Rodriguez. Help is welcome with reproducible bug reports, platform compatibility, installation documentation, and small regression fixes.

## Start with an issue

Use [the issue tracker](https://github.com/eabdiel/pAR3D/issues) to describe a bug or propose an improvement. Include your operating system, application version or commit, reproduction steps, expected behavior, and actual result. Use small synthetic examples and sanitized logs; omit credentials, private records, and customer data.

For larger changes, describe the intended behavior and discuss scope before implementation. Do not assume that an idea in the roadmap is already implemented.

## Submit a focused pull request

1. Fork the repository and create a branch for one change.
2. Follow the setup and limitations in the README and relevant project documentation.
3. Update documentation alongside changed behavior.
4. Run the relevant checks and state exactly what you verified, including platform or hardware limitations. A documentation-only change can be checked by previewing Markdown and verifying links.
5. Explain the problem, resulting behavior, validation, and any remaining limitations in the pull request.

## Licensing and attribution

The repository includes GPL-3.0 terms in [LICENSE](LICENSE). Preserve applicable copyright and license notices. Consult the full license for modification, distribution, and any source-provision requirements.

Depth Anything V2 model checkpoints have separate upstream terms. Confirm the exact checkpoint before redistribution or commercial use: [upstream licensing](https://github.com/DepthAnything/Depth-Anything-V2#license). The application’s GPL license does not relicense model weights.

Only submit material you have permission to contribute. Identify reused code, dependencies, datasets, model weights, images, and other assets by upstream URL, version or revision, and license. Retain required notices and describe modifications. The existing project and component licenses govern; this guide creates no new copyright assignment or license grant. If license scope is unresolved, start with documentation feedback or a licensing discussion before submitting code.

## Working together

Keep discussion respectful, concrete, and focused on the project. Useful reports and documentation contributions matter as much as code. Do not post security-sensitive details in a public issue; use GitHub private vulnerability reporting if the repository offers it.
